Лабораторна робота №2
тема: Використання розробки на основі тестування (TDD)

Мета роботи
Ознайомитися з методологією розробки програмного забезпечення на основі тестування (Test Driven Development, TDD), 
закріпити навички модульного тестування та практично реалізувати TDD-підхід під час розробки бібліотеки операцій над матрицями з використанням засобів Mocha та Chai.

Теоретичні відомості
Розробка на основі тестування (Test Driven Development, TDD) — це методологія розробки програмного забезпечення, 
яка передбачає написання модульних тестів до створення програмного коду. Основна ідея TDD полягає в тому, що функціональні 
вимоги до системи спочатку формалізуються у вигляді тестів, а вже потім реалізується код, який ці тести задовольняє.

Класичний цикл TDD складається з трьох послідовних етапів:
Red — створення тесту, який описує очікувану поведінку, але не проходить через відсутність реалізації;
Green — написання мінімального програмного коду, необхідного для успішного проходження тесту;
Refactor — покращення структури та якості коду без зміни його зовнішньої поведінки.
Даний підхід сприяє створенню простого, надійного та добре протестованого програмного коду.

Практична частина
У межах лабораторної роботи реалізовано міні-бібліотеку операцій над матрицями MtrxLite, що демонструє застосування підходу TDD на практиці.
Розробка здійснювалась у такій послідовності:
Створення модульних тестів для основних операцій над матрицями (створення, додавання, транспонування).
Реалізація мінімального функціоналу для проходження тестів.
Рефакторинг коду без зміни його поведінки.
Автоматизація запуску тестів за допомогою GitHub Actions.
Для модульного тестування використано бібліотеки Mocha (тестовий фреймворк) та Chai (бібліотека асерцій).

Запуск тестів
Для запуску модульних тестів використовується команда:
npm test

Тести автоматично запускаються під час кожного push або pull request завдяки налаштованому workflow GitHub Actions.

Контрольні запитання
1. Наведіть особливості TDD підходу.
Основними особливостями підходу Test Driven Development є:
написання тестів до реалізації програмного коду;
ітеративний цикл розробки Red → Green → Refactor;
реалізація лише мінімально необхідного коду для проходження тестів;
постійна перевірка коректності змін за допомогою автоматичних тестів;
зменшення кількості помилок та регресій у програмному коді.
TDD сприяє створенню більш зрозумілого, модульного та підтримуваного програмного забезпечення.

2. Як модульне тестування використовується у методології TDD?
У методології TDD модульне тестування є основним інструментом керування процесом розробки.
Кожна функція або метод розглядається як окремий модуль, для якого створюються тести, що перевіряють:
правильність результатів;
обробку помилкових або граничних значень;
відповідність очікуваній поведінці.
Модульні тести виконуються після кожної зміни коду та забезпечують швидке виявлення помилок, а також слугують захистом від порушення вже реалізованого функціоналу.

3. Як враховується специфікація програмного забезпечення та на якому етапі?
У підході TDD специфікація програмного забезпечення враховується на етапі написання тестів.
Функціональні вимоги перетворюються на набір тестових сценаріїв, які чітко описують очікувану поведінку системи.
Таким чином:
тести виступають формалізованою специфікацією;
кожна вимога є перевірюваною автоматично;
реалізація вважається завершеною лише після успішного проходження відповідних тестів.
Це забезпечує точну відповідність коду вимогам та підвищує якість програмного продукту.
